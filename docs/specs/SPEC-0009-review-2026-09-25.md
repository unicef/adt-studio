## Findings fixed

All findings below were reproduced with failing tests before correction. Severity reflects their concrete impact, not the amount of code changed.

| Severity | Finding and causal path | Correction and regression evidence |
|---|---|---|
| P1 | Changing pages inside the Preview iframe bypassed the app route guard and reset an unsaved review. Separately, direct Save permitted further edits and Save & leave could issue a second request; the first completion could clear a newer draft. Direct save rejection had no visible error. | `PreviewValidationCard` pins the draft to its source page until save/discard, disables session changes while dirty, shares one save promise, freezes edits during saving and displays retryable failures. `ValidationNavigation.test.tsx` changes the iframe page, checks the saved source identity, joins direct Save with Save & leave, and verifies failure/retry without losing notes. |
| P1 | Saving a reviewer record inserted it into every cached page-results query for the book, including another session, page or language. The wrong review could be shown or used to initialize a draft before refetch. This was an existing adjacent cache bug exposed by tracing the changed save flow. | `use-reviewer-validation` updates only matching query scopes. The new hook test uses a real QueryClient and a stubbed API boundary, asserting unaffected cached records stay unchanged. |
| P2 | A Sectioning repair can invalidate Storyboard. Validation then replaced its entire UI with a blocked-stage screen, making the promised historical return context inaccessible. | `ValidationView` keeps historical findings readable while disabling explicit refresh until output is eligible. Parameterized tests cover incomplete Storyboard and all-pruned output, with no task admission. |
| P2 | An axe rule present in both confirmed violations and manual-review findings had the same return identity and DOM ID. Return could focus the confirmed card after opening the manual finding. Deleted assessments also lacked an explicit return explanation. | Finding context and IDs now distinguish `review:` from `violation:`. Component tests verify the correct card receives focus and a deleted assessment is explained without claiming a pass. |
| P2 | The explicit Return to Validation button dropped unrelated query parameters and the fragment, even though browser Back preserved them. | Outward and explicit return navigation carry unrelated search/hash state and remove only consumed routing context. The real TanStack memory-router test verifies both Return and Back. |
| P2 | An identity unique during inventory lookup could become duplicated before editor data arrived. Sectioning/Storyboard would focus an arbitrary matching section. | Both editors require exactly one active match immediately before focus; otherwise they consume the request and show the existing unavailable-target notice. Destination component tests cover the intervening ambiguity. |
| P2 | Legacy sessions without a checklist snapshot displayed old answers under labels from the edited live checklist, implying an unverified historical meaning. | Reviewer summary preserves the criterion ID with an unknown-label fallback instead of borrowing a current label. The regression changes the live catalog while retaining the historical answer and legacy ownership fallback. |

The review also retraced immutable session snapshots through HTTP validation, versioned book storage and readback; stable target resolution through inventory and destination loading; and navigation through the shared unsaved-state guard. No renderer, entity migration or new dependency was introduced by these review fixes. Navigation still performs no content or verdict writes, and heading-order repairs retain the published Storyboard default.
