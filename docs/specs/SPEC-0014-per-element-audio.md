## Problem (with evidence)

ADT reads a whole section aloud: `useAudioPlayer` gathers every `[data-id]` element that has an
entry in `audios.json` and plays them **sequentially**. There is **no way to play one element's
audio on interaction**, and no way for an author to say what a given element should sound like.

That gap blocks the activities the *Dale* book needs, which ask the learner to "tap the picture and
hear its name". Recorded in the project's own working notes as a transversal gap: *"Tap-to-play en
imágenes — no existe en ADT"* (`progress.md` §5, five separate pages affected).

Anchors (verified against `develop` at `737d3314`):

- **The player is sequential.** `gatherPlayableItems` builds the list from `[data-id]` +
  `audioFiles` (`apps/adt-runtime/src/features/audio/hooks/useAudioPlayer.ts:93-119`);
  `playAtIndex` chains to the next item on `ended` (`:320-329`). No per-element trigger exists.
- **Images are excluded from the sweep** unless `describeImagesMode` is on (`:184-193`).
- **Images have no catalog entry unless captioned.** `text-catalog.ts:95-100` emits an entry for an
  `<img data-id>` only when `image-captioning` produced a caption. Measured on a seeded book: a page
  with one text leaf and one uncaptioned image produced the catalog
  `{pg001_h001, pg001_t001}` — **nothing for the image**.
- **No per-element playback exists anywhere.** A repo-wide grep across all refs for
  `data-audio-src`, `data-speech-id`, `tapToPlay` and `playAudioFor` returns **no matches**.
- **Authorship lives in the wrong place.** The only speech-text editor is
  `CoreTtsSpeechEditor.tsx`, rendered inside the **Languages** stage (`LanguageView.tsx:1568`), not
  where the author selects an element in the Storyboard.

### The obvious implementation does not survive regeneration (measured)

The cheapest design is to inject a synthetic catalog entry. It works — but it does not persist.
Both results come from a throwaway probe (finding:
[`docs/experiments/890-element-audio-survival.md`](../experiments/890-element-audio-survival.md)):

**It works.** With `{ id: "pg001_im001_audio", text: "Mago" }` inserted into `text-catalog`:

| Step | Observed |
|---|---|
| `prepareCoreTtsCatalog` | `displayText: "Mago"`, `speechText: "Mago"`, `status: "ready"` — **no LLM call** (no transformations enabled) |
| `generateSpeechFile` | wrote `books/<label>/audio/es-UY/pg001_im001_audio.mp3` |
| packaging maps | `speech_texts.json` and `audios.json` both included the synthetic id |

**It does not persist.** Running `buildTextCatalog` again **deleted the entry** — the catalog is
rebuilt from the rendered HTML, so nothing that did not come from the HTML survives:

```
before: catalog contains "pg001_im001_audio"
after : entries = pg001_h001, pg001_t001      ← gone
```

And the invalidation machinery clears the whole chain. Executing the real functions:

| Node | `easy-read` | `translate` rerun | image-set change |
|---|---|---|---|
| `text-catalog` | ✅ | — | ✅ |
| `text-catalog-translation` | ✅ | ✅ | ✅ |
| `core-tts-catalog` | ✅ | — | ✅ |
| `tts` | ✅ | ✅ | ✅ |

`getStageClearNodes("easy-read")` includes `text-catalog` — **the step that builds the catalog clears
it first**. `IMAGE_SET_CHANGE_CLEAR_NODE_TYPES` clears `text-catalog` book-wide, so **changing any
image destroys the authored text of the entire book**.

### In-flight work this must compose with, not duplicate

**PR #710** (`feature/selective-speech-regeneration`, open, closes #696) already provides: a
per-entry content hash (`SpeechFileEntry.sourceHash`), reuse by comparing that hash
(`canReuseSpeechEntry`: `entry.sourceHash === cacheKey`), content-hashed audio filenames
(`${textId}.${hash.slice(0,12)}.${format}`), a `forceRegenerate` bypass, an optional arbitrary
`text` on `POST /tts/generate-one`, and per-provider single-item generation (previously Gemini-only).
Its `persistCatalogTextVersion` writes the edited text into `text-catalog` /
`text-catalog-translation` — **inheriting the data loss documented above**, which is why this spec
keeps authored text in its own artifact (§Proposed design) and uses #710 only as the synthesis and
versioning primitive. #710 also **changes the audio filename contract**, which this spec's packaging
remap must be written against.

## Goals

- An author can select an element in the Storyboard and **type the text it should speak**.
- ADT generates the audio. No file upload, no video.
- Clicking the element plays **its** audio, in the reader **and** in the Storyboard preview.
- **One audio per element**, used by both the click and the read-aloud sweep.
- A **visual indicator** makes the audio discoverable.
- The authored text **survives** content regeneration, sectioning reruns and image changes.
- Text is authored in the book's source language; translation happens only when a target language
  exists (no current book has one).

## Non-goals

Binding.

- **No external media upload** and **no video**. (`POST /tts/upload-one` exists and stays as-is; it is
  not this feature's flow.)
- **No multi-language translation in v1.** Every book in the working set is single-language
  (`editing_language: es-UY`, `output_languages: [es-UY]`), so `getTargetLanguages`
  (`catalog-translation.ts:39-48`) returns `[]` and `catalog-translation` translates nothing. The
  design must not *preclude* it: because the script enters the catalog as an ordinary entry,
  translation activates by itself once a book declares a second output language.
- **Web export only.** EPUB, WebPub and PNLD are out of scope (EPUB currently deletes
  `audio_voices.json`, `packaging/epub.ts:91-92`).
- **No change to TTS providers, voice routing, `voices.yaml`, or the speech cache key.**
- **No new element types**, no new activity runtime, no memory/card activity.
- **No redesign of staleness or invalidation** — that is SPEC-0001's territory. This spec avoids
  depending on it.
- **No `pnpm acceptance` harness** — it does not exist (SPEC-0005 is a draft).

## Proposed design

### 1. Authored text lives in its own artifact

A new `node_data` node, **`element-audio`**, with `item_id = pageId` and payload
`{ entries: [{ nodeId, text }], generatedAt }` — the same shape as the existing per-page
`image-captioning` node (`text-catalog.ts:158-173`).

Why this is safe and cheap (all verified):

- **No schema migration.** `node_data.node` is free `TEXT` (`packages/storage/src/db.ts:22-28`); the
  experiment wrote a new node without touching the schema.
- **Versioning and rollback for free** (Principle 2) via `putNodeData`.
- **Outside every clear list**, so it does not suffer the loss measured above. It must be
  **deliberately kept out of all of them** — there are **13 `clearNodesByType` call sites** across the
  API, and only two of them are derived lists:

  | Derived | Ad-hoc literals |
  |---|---|
  | `getStageRerunClearNodes` → `stages.ts:194`; `IMAGE_SET_CHANGE_CLEAR_NODE_TYPES` → `pages.ts:462`, `glossary.ts:159` | `books.ts:418` (11 nodes), `page-edit-service.ts:216` (8), `easy-read.ts:125`, `pages.ts:502`, `:523`, `:1748`, plus the `["accessibility-assessment"]`-only sites (`pages.ts:552`, `:615`, `:626`, `text-catalog.ts:187`, `:307`, `fonts.ts:588`, `tts.ts:575`) |

  The ad-hoc ones are the risk: `books.ts:418` is a hand-written eleven-node list, exactly the kind a
  later change extends by copy-paste.

**Orphan policy — ratified (owner, 2026-09-23).** Deleting an element **keeps** its authored text.
No garbage collection is added in v1; the artifact may accumulate entries for removed nodes. Revisit
alongside **SPEC-0008** (stable identifiers), which is what would make a `nodeId` reusable and
therefore make an orphan dangerous rather than merely dead weight.

**How it is read and written.** Through the artifact's own route —
`GET` / `PUT /books/:label/pages/:pageId/element-audio` — with **immediate save**. It deliberately does
**not** travel inside the Storyboard save payload and does not participate in `pendingSectioning`, the
floating save bar or the dirty chips: the script is a per-page entity of its own, and §3's generation
rule already makes it independent of the render. Precedent: `CoreTtsSpeechEditor` saves through
`updateCoreTtsEntry` immediately, with its own button and its own error state.

The node name must be registered in **both** places where versionable node names are enumerated — the
API's `RestorableNode` (`apps/api/src/routes/pages.ts:466-477`) and the Studio's `VersionedStep`
(`VersionPicker.tsx:46-56`). Those are the same ten-name list duplicated in two files, with nothing
coupling them, so the two edits have to be made together: the Studio side is compiler-enforced
(`Record<VersionedStep, …>`), but the API's `switch` has no `default` and returns `void`, so **a
missing case compiles and silently invalidates nothing**.

### 2. Production reuses the existing chain

```
element-audio (authored, per page)
      │  buildTextCatalog reads the artifact (it already has storage + pageId)
      ▼
text-catalog: synthetic entry { id: `${nodeId}_audio`, text }
      │
easy-read → text-catalog → (translate → catalog-translation) → core-tts-catalog → tts
      │
package-web
      ▼
remap: audios[nodeId] = <file of `${nodeId}_audio`>,  speech_texts[nodeId] = script
```

The synthetic id is **internal plumbing**. Publishing under the **element's own id** means the
runtime needs no new lookup: `gatherPlayableItems` already resolves by `data-id`, so the click and
the sequential sweep share one audio with no change to the resolution path.

**The remap must be applied in two places**, or preview and bundle disagree:

1. `packages/pipeline/src/packaging/web.ts` (the bundle), and
2. the preview mirrors in `apps/api/src/routes/adt-preview.ts` — `audios.json` (`:789`),
   `audio_voices.json` (`:819`), audio bytes (`:954`).

### 3. Generation is on demand

The script is saved immediately; **audio is generated when the author runs Speech**, never on save.

**Ratified (owner, 2026-09-23).** A single-element regeneration follows an **#710-conditional** rule:

- **If #710 has landed:** use the optional `text` parameter on `POST /tts/generate-one` for the point
  path — one element regenerates in a single call, and the stages catch up on their next run.
- **Otherwise:** accept running the `easy-read → translate → speech` chain for that element.

The reason a rule is needed at all: the text catalog is built in the **`easy-read`** stage while
synthesis happens in **`speech`**, so a newly authored script cannot be synthesized by running
`speech` alone. This rule keeps the cheap path available without blocking on #710.

**What becomes stale, and what is preserved.** Changing one element's script makes **only that
element's** audio stale — never another element's, never another page's.

- **With #710 landed:** nothing needs deleting. Its `canReuseSpeechEntry` compares the recorded
  `sourceHash` against the hash of the current text, so the entry is detected as stale and regenerated
  on the next run.
- **Without #710:** remove **only that `textId`** from the `tts` node, and never remove entries whose
  `provider` is `"manual"` — uploaded recordings are user-owned. This is the codebase's established
  idiom rather than a new one: the `core-tts-catalog` restore case
  (`apps/api/src/routes/pages.ts:563-623`) computes changed ids by comparing before/after and filters
  `tts` and `tts-timestamps` exactly this way.

**Restoring an earlier version of the script clears nothing.** `element-audio` is user-authored
content, not a derived output, so its case in `clearRestoredNodeDependents` must not call
`clearNodesByType`: restoring an older script only makes the derived audio stale. It is likewise **not**
added to any other node's clear list — which is precisely why it survives a `page-sectioning` restore,
since that path calls `clearCaptionData`, clearing `IMAGE_SET_CHANGE_CLEAR_NODE_TYPES`.

### 4. The runtime adds the click trigger and the indicator

- A click on an element that has audio plays that element's audio (and stops the current one).
- **Ratified (owner, 2026-09-23): the icon badge is added by the _runtime_, not by the rendered
  HTML.** That keeps the rendered HTML, the prompt contract and `validate-html.ts` untouched, and it
  means the badge exists in both the preview and the bundle for free — the preview serves the same
  runtime (`adt-preview.ts:549-556`).
- **Ratified (owner, 2026-09-23): the badge ships in the export, and is hidden in `@media print`.**
  The reader cannot discover the audio without it; a printed page should not show it.
- Elements that are not audio-bearing keep today's behaviour exactly.

### 5. Accessibility is enforced by an existing automatic audit

`runAccessibilityAssessment` runs **axe-core** as a pipeline step, with
`DEFAULT_AXE_RUN_ONLY_TAGS` including **`best-practice`**, **`cat.keyboard`**, `cat.text-alternatives`
and `cat.name-role-value` (`accessibility-assessment-shared.ts:13-32`); only `color-contrast` is
disabled (`:34`). It runs in **JSDOM with `runScripts: "outside-only"`
(`accessibility-assessment.ts:130-134`), so the click handler does not execute during the audit —
only the **static attributes** are checked**. It **reports** violations and summarises them
(`:242-255`); it does not fail the run.

**These requirements were measured, not derived.** A probe reproduced the audit's exact
configuration — same tags, same disabled rule, same JSDOM options — against each candidate shape for
a clickable element:

| Shape | Result |
|---|---|
| `<img tabindex="0">`, no role | **clean** — `focus-order-semantics` is *inapplicable* to `<img>` |
| `<img tabindex="0" role="button" alt="Mago">` | clean |
| `<img tabindex="0" role="button">` with no `alt` | `aria-allowed-role` (minor) + `image-alt` (**critical**) |
| `<img tabindex="1">` (positive) | **`tabindex` (serious)** — never use a positive value |
| `<div tabindex="0">`, no role | **`focus-order-semantics` (minor)** |
| `<p tabindex="0" role="button" aria-label="…">` | clean |
| `<span role="button" tabindex="0">` with no accessible name | **`aria-command-name` (serious)** |
| a clickable element nested inside a `<button>` | **`nested-interactive` (serious)** |

So the constraint is **not** "every click target needs a role". It is:

- **An `<img>` target needs only `tabindex="0"` plus a meaningful `alt`.** `role="button"` is optional;
  when added, the accessible name still resolves from `alt` (verified clean) — but a missing `alt`
  becomes a **critical** `image-alt` violation.
- **A non-`img` target must carry an interactive role _and_ an accessible name** the moment it is
  focusable, or `focus-order-semantics` / `aria-command-name` fire.
- **Never a positive `tabindex`.**
- **Never nest the click target inside another interactive control** (`nested-interactive`, serious),
  which rules out making an activity item that is already a button into a click-to-play target.
- The badge must be `aria-hidden="true"` and must not steal the click.

## Impact map

**Packages / files (expected)**

- `packages/types`: `ElementAudioOutput` schema; the synthetic id helper; registration of the node
  name where node names are enumerated.
- `packages/pipeline`: `text-catalog.ts` (read the artifact, emit synthetic entries);
  `packaging/web.ts` (the remap); `accessibility-assessment-shared.ts` only if a rule needs
  excluding (not planned).
- `apps/api`: routes to read/write the artifact; a `case` in the per-node `switch` in
  `apps/api/src/routes/pages.ts:493-625` (versions / restore); the preview manifest mirrors in
  `adt-preview.ts`.
- `apps/studio`: a new section in `StyleEditorPanel` (via `SectionKey` + `SECTION_COMPONENTS` +
  `VISIBLE_SECTIONS`); the save path; registering the node in
  `VersionPicker.tsx:49-79`; i18n in all five locales.
- `apps/adt-runtime`: the click trigger in the audio feature; the badge; a11y attributes.

**Invariants affected**

- **Entity versioning** (registry row 2: *no unconditional clear/DELETE of user-touched entities*).
  This spec establishes `element-audio` as a user-touched entity, so it **adds the registry row and
  its checker in the same change**. `pnpm lint:invariants` does not exist yet; per
  `docs/SPEC_DRIVEN_DEVELOPMENT.md` §7, **the first spec that needs it introduces it**.
- Not affected: stable identifiers (we reuse `nodeId`), prompt contracts (no prompt changes), layer
  rules.

**Data / schema migration:** **none.**

**Collides with**

- **#710** — same files (`packages/pipeline/src/speech.ts`, packaging) and it changes the audio
  filename contract. Sequence deliberately; coordinate before the first PR.
- **SPEC-0001 / SPEC-0002** — both touch invalidation. This spec is designed **not** to depend on
  them (it avoids the cleared nodes entirely).
- **SPEC-0008** — stable identifiers. This spec assumes `nodeId` never gets reassigned; if SPEC-0008
  find otherwise, the orphan rule needs revisiting.

## Acceptance criteria

- [ ] **AC-1** An author can select an element in the Storyboard and save a spoken text for it; the text persists as a new version of the `element-audio` node for that page.
- [ ] **AC-2** After running the pipeline, the element's audio exists on disk and the packaged `audios.json` / `speech_texts.json` publish it **under the element's own `data-id`**.
- [ ] **AC-3** Clicking the element in the exported reader plays **only** that element's audio and pauses any audio already playing.
- [ ] **AC-4** The same element is played by the sequential read-aloud sweep using the **same** audio file (one audio, two triggers).
- [ ] **AC-5** An element whose spoken text differs from its visible text (an uncaptioned image) still gets audio, and no word-level highlight is attempted for it (block highlight only).
- [ ] **AC-6** The authored text **survives**: re-running `easy-read` / `text-catalog` / `catalog-translation` / `core-tts-catalog`, and changing the book's image set, leave `element-audio` intact.
- [ ] **AC-7** No code path adds `element-audio` to a clear/delete list; the invariant checker fails CI if one is added.
- [ ] **AC-8** Deleting an element **keeps** its authored text; duplicating an element produces a clone **without** audio, and the UI says so rather than failing silently.
- [ ] **AC-9** A clickable element passes the audit once interactive, per the measured recipe in §5: an `<img>` carries `tabindex="0"` and a meaningful `alt`; a non-`img` element additionally carries an interactive role **and** an accessible name; no element uses a positive `tabindex`; and nothing is nested inside another interactive control. The axe-core assessment reports **no new violations** on a page with element audio versus the same page without it.
- [ ] **AC-10** The visual indicator is decorative to assistive tech (`aria-hidden`) and does not intercept the click.
- [ ] **AC-11** Element audio appears in the **Storyboard preview** with identical behaviour to the bundle.
- [ ] **AC-12** A book with `output_languages` equal to its source language produces element audio with **zero** translation calls (v1 is single-language).
- [ ] **AC-13** All new user-visible strings are wrapped in Lingui macros and translated in `en`, `pt-BR`, `es`, `fr`, `sq`; the i18n CI job passes.
- [ ] **AC-14** Existing books (no `element-audio` node) open and export unchanged.
- [ ] **AC-15** Changing one element's script makes **only that element's** audio stale: no other element's audio and no other page is invalidated. Restoring an earlier version of a script deletes nothing.

## Rollout

Three independently revertable PRs, each within the ~400-line review budget of
`docs/SPEC_DRIVEN_DEVELOPMENT.md` §9. **None ships a user-visible change until PR 3.**

1. **PR 1 — plumbing, no UI.** `element-audio` schema + storage read/write + `buildTextCatalog`
   emitting synthetic entries + the invariant row and its checker. Value: verifiable by test that an
   authored script produces audio.
2. **PR 2 — authoring.** The Storyboard inspector section, the save path, node registration in the
   version picker, invalidation wiring, i18n. Value: the author can write the script.
3. **PR 3 — playback.** The packaging remap (bundle **and** preview mirrors), the runtime click
   trigger and badge, and the a11y attributes. Value: the reader hears it.

No feature flag; each PR reverts alone.
