## Problem (with evidence)

ADT reads a whole section aloud: `useAudioPlayer` gathers every `[data-id]` element that has an
entry in `audios.json` and plays them **sequentially**. There is **no way to play one element's
audio on interaction**, and no way for an author to say what a given element should sound like.

That gap blocks the activities the *Dale* book needs, which ask the learner to "tap the picture and
hear its name".

Anchors (verified against `develop` at `8b454f658`):

- **The player is sequential.** `gatherPlayableItems` builds the list from `[data-id]` + `audioFiles`
  (`apps/adt-runtime/src/features/audio/hooks/useAudioPlayer.ts:95`); `playAtIndex` chains to the next
  item on `ended` (`:364-368`). No per-element trigger exists.
- **Images are excluded from the sweep** unless `describeImagesMode` is on (`:175/204`); authored
  images are the exception added in §4.
- **Images have no catalog entry unless captioned.** `text-catalog.ts` emits an entry for an
  `<img data-id>` only when `image-captioning` produced a caption (`:96-100`). Measured on a seeded
  book: a page with one text leaf and one uncaptioned image produced the catalog
  `{pg001_h001, pg001_t001}` — **nothing for the image**.
- **No per-element playback exists anywhere.** A repo-wide grep across all refs for `data-audio-src`,
  `data-speech-id`, `tapToPlay` and `playAudioFor` returns **no matches**.
- **Authorship lives in the wrong place.** The only speech-text editor is `CoreTtsSpeechEditor.tsx`,
  rendered inside the **Languages** stage (`LanguageView.tsx:2692/2816/2914/2945`), not where the
  author selects an element in the Storyboard.

### The obvious implementation does not survive regeneration (measured)

The cheapest design is to inject a synthetic catalog entry. It works — but it does not persist. Both
results come from a probe (finding:
[`docs/experiments/890-element-audio-survival.md`](../experiments/890-element-audio-survival.md)):

**It works.** With `{ id: "pg001_im001_audio", text: "Mago" }` inserted into `text-catalog`:
`prepareCoreTtsCatalog` produced `displayText/speechText: "Mago"` with **no LLM call**,
`generateSpeechFile` wrote `audio/es-UY/pg001_im001_audio.mp3` (the probe predates the immutable
filename contract), and the packaging maps included the synthetic id.

**It does not persist.** Running `buildTextCatalog` again **deleted the entry** — the catalog is
rebuilt from the rendered HTML, so **nothing that did not come from the HTML survives**:

```
before: catalog contains "pg001_im001_audio"
after : entries = pg001_h001, pg001_t001      ← gone
```

This is the load-bearing reason for a separate artifact, and it holds on **every** branch: the
catalog stays *derived from the rendered HTML* (SPEC-0001 keeps it "derived from the latest saved
authored content, not a second editable source of truth"). A script that is not part of the HTML
therefore cannot live only in the catalog.

### How the invalidation contract changed (SPEC-0001/0002) — and why it doesn't change the decision

The probe executed the invalidation functions on pre-SPEC-0001 `develop`, where `clearNodesByType`
**deleted**:

| Node | `easy-read` | `translate` rerun | image-set change |
|---|---|---|---|
| `text-catalog` | ✅ | — | ✅ |
| `text-catalog-translation` | ✅ | ✅ | ✅ |
| `core-tts-catalog` | ✅ | — | ✅ |
| `tts` | ✅ | ✅ | ✅ |

`getStageClearNodes("easy-read")` included `text-catalog` — **the step that builds the catalog
cleared it first** — and `IMAGE_SET_CHANGE_CLEAR_NODE_TYPES` cleared `text-catalog` book-wide, so on
that `develop` changing any image destroyed the authored text of the entire book.

**Merged develop changes that premise**: `clearNodesByType` no longer deletes non-catalog rows — it
writes `NULL` invalidation versions (`book-storage.ts:83-99`) and skips `CATALOG_OUTPUT_NODES` — and
`clearCaptionData` clears only `accessibility-assessment`. So "an image change wipes the book's
catalog" is **not** true today. This spec **does not rest on that premise**: it rests on the
derived-catalog reason above, which is why it still keeps its own artifact. The invalidation table is
kept as the measurement that motivated the probe, not as the justification.

## Goals

- An author can select an element in the Storyboard and **type the text it should speak**.
- ADT generates the audio. No file upload, no video.
- Clicking the element plays **its** audio, in the reader **and** in the Storyboard preview.
- **One audio per element**, used by both the click and the read-aloud sweep.
- A **visual indicator** makes the audio discoverable.
- The authored text **survives** content regeneration, sectioning reruns and image changes.
- Text is authored in the book's source language; translation happens only when a target language
  exists (no current book has one).

## Non-goals

Binding.

- **v1 covers image leaves only.** Text and container leaves are **out of scope** until
  **SPEC-0008 / #834** make their ids stable: `finalizePageSectioning`
  (`packages/pipeline/src/page-sectioning.ts:685,713`) mints text/container ids **by position**
  (`${pageId}_nNNNN`) on every re-section, so a script keyed by a text `nodeId` could silently
  reattach to different text. Image ids (`pg001_im001`) come from extraction
  (`page-sectioning.ts:704-706`) and are stable. The artifact **schema stays generic** (`entries: [{
  nodeId, text }]`) so enabling text later needs no migration.
- **Cloning a section does not inherit element audio.** `cloneNodesWithFreshContainerIds`
  (`apps/api/src/routes/pages.ts:822`) keeps leaf ids, so a clone would share the original's script.
  Out of scope in v1; recorded, not silently implemented.
- **Deleting a page and a full re-extraction destroy the artifact.** `deletePage`
  (`packages/storage/src/book-storage.ts:119`, called from the spreads reconcile) hard-deletes
  everything for the page; `clearExtractedData` (`:77`, via `clearExtractedRows` at `:655`) clears
  every node except the font ones. Both are "the source is gone" paths, so losing the script is
  legitimate and documented rather than defended.
- **Round-trip import (#803) and offline regeneration (#700) do not reconstruct or preserve it.**
  #803 rebuilds from a bundle and has no `element-audio` concept; #700 regenerates `audios[textId]`
  from `texts.json`. The implementing PR must ensure **#700 does not overwrite authored element
  audio** (see Options, PM-listed).
- **The standalone activities bundle is out of scope** — it has no `AudioPlayerProvider` at all.
- **No external media upload** and **no video**. (`POST /tts/upload-one` exists and stays as-is.)
- **No multi-language translation in v1.** Every book in the working set is single-language, so
  `catalog-translation` translates nothing. The design must not *preclude* it: because the script
  enters the catalog as an ordinary entry, translation activates by itself once a book declares a
  second output language.
- **Web export only.** EPUB, WebPub and PNLD are out of scope (EPUB deletes `audio_voices.json`).
- **No change to TTS providers, voice routing, `voices.yaml`, or the speech cache key.**
- **No new element types**, no new activity runtime.
- **No redesign of the staleness or invalidation model** — that is SPEC-0001's territory. This spec
  only adds id-level exclusions so its own synthetic entries do not widen it.

## Proposed design

### 1. Authored text lives in its own versioned artifact

A new `node_data` node, **`element-audio`**, with `item_id = pageId` and payload
`{ entries: [{ nodeId, text }], generatedAt }` — a **new** schema (not the `image-captioning` shape,
whose payload is `{ captions: [...] }`, `packages/types/src/image-captioning.ts:25`).

Why this is safe and cheap (all verified):

- **No schema migration.** `node_data.node` is free `TEXT` (`packages/storage/src/db.ts`).
- **Versioning and rollback for free** (Core Principle 2) via `putNodeData`.
- **It is authored content, not a derived output**, so it does **not** carry the `OutputMetadata`
  provenance that SPEC-0001 adds to `text-catalog` / `core-tts-catalog` / `tts`: those describe
  *generated* outputs. `element-audio` is the authoritative store for user input (ADR-028).

**Registration.** The node name must be added everywhere node names are enumerated — they are
duplicated and nothing couples them:

- `RestorableNode` (`apps/api/src/routes/pages.ts:571`) and `VersionedStep` (`VersionPicker.tsx:46-56`,
  with its `STEP_STYLING` record at `:68-79`). On merged develop restore is uniform:
  `clearRestoredNodeDependents` (`pages.ts:593`) marks the source generation and clears captions;
  there is no per-node `switch` to extend, so adding the node to `RestorableNode` is the whole
  API-side change.
- `PipelineNodeName` and `NODE_CACHE_RESOURCES` (`packages/types/src/pipeline-effects.ts:11,124`).
- **Not** `CATALOG_OUTPUT_NODES`: it is authored content and must never be invalidated.

**Clear-list exclusion.** There are **8 `clearNodesByType` call sites** in `apps/api/src` (source
scan, excluding tests), all on merged develop: `easy-read.ts:79`, `fonts.ts:588`,
`glossary.ts:164`, `pages.ts:510`, `stages.ts:167`, `text-catalog.ts:271/365`,
`page-edit-service.ts:229`. Two are derived lists (`getStageRerunClearNodes`,
`IMAGE_SET_CHANGE_CLEAR_NODE_TYPES`); the rest are ad-hoc literals. On merged develop
`clearNodesByType` no longer deletes non-catalog rows — it writes a `NULL` invalidation version
(`book-storage.ts:83-99`), so "cleared" means hidden with history kept — but `element-audio` must
appear in **none** of them, and the checker (AC-7) enforces that.

**Orphan policy.** Deleting an element **keeps** its authored text. No garbage collection in v1;
revisit with SPEC-0008.

**How it is read and written.** Through the artifact's own route —
`GET` / `PUT /books/:label/pages/:pageId/element-audio` — with **immediate save**. It deliberately
does **not** travel inside the Storyboard payload and does not use `pendingSectioning`, the floating
save bar or the dirty chips. Precedent: `CoreTtsSpeechEditor` saves through `updateCoreTtsEntry`
immediately, with its own button and error state.

**Identity reservation.** The synthetic id is `${nodeId}_audio`, so a rendered `data-id` ending in
`_audio` could collide with it. `collectSpentContentIds` and `findIntroducedDerivedIdCollision`
(`packages/pipeline/src/content-ids.ts:40-50,104-110`) already reserve both directions of the
`_easy_read` pair; the same change must reserve `${imageId}_audio` (and the reverse) and reject a
draft that introduces both sides. The synthetic entry carries
`locations: [{ pageId, sectionId: <the image's section>, role: "element-audio" }]`, so ownership,
conflict reporting and packaging read the explicit location. Batching deliberately does **not**:
`speechPageId` returns `undefined` for `_audio` (see §2), so the location's `pageId` never makes the
node join a page batch.

**Concurrency guard.** The node is one versioned row per page holding every image's script, so two
editors on the same page must not lose each other's work. The `PUT` carries `baseVersion`. It follows
the `core-tts-catalog` speech-entry PUT (`apps/api/src/routes/text-catalog.ts:283`) rather than
`assertEditVersion`: when `current.version !== baseVersion`, it loads the row at `baseVersion` from
history (`:317-319`), diffs the submitted entries against that baseline, applies only the `nodeId`s
whose text actually changed, and preserves entries added by the other writer. If the **same**
`nodeId` changed on both sides since `baseVersion`, it returns 409 with the current version
(`:328`). It does **not** call `assertEditVersion`, which would reject every stale save before the
merge could run. AC-1 asserts both the merge and the 409.

### 2. Production reuses the existing chain, and flows through catalog freshness

```
element-audio (authored, per page)
      │  buildTextCatalog reads the artifact (it already has storage + pageId)
      ▼
text-catalog: synthetic entry { id: `${nodeId}_audio`, text }
      │
easy-read → text-catalog → (translate → catalog-translation) → core-tts-catalog → tts
      │
package-web (+ adt-preview mirrors)
      ▼
remap: audios[nodeId] = <file of `${nodeId}_audio`>,  speech_texts[nodeId] = script
        element_audio.json lists the authored ids; texts.json excludes them
```

- The synthetic id is **internal plumbing**. Publishing under the **element's own id** means the
  runtime resolves the audio with its existing `data-id` lookup (`gatherPlayableItems`) and never
  sees `${nodeId}_audio`.
- **Runtime discovery.** Resolution is not discovery: `audios[nodeId]` also exists for captioned
  images, so the map alone cannot tell authored audio from ordinary narration. The remap therefore
  also writes a per-language **`element_audio.json`** — a JSON array of the `data-id`s whose audio
  was actually published from the authored script. The runtime fetches it optionally; an absent or
  empty file means today's behaviour exactly. The badge, the click trigger and the sweep inclusion
  read that set (AC-20), so existing books never gain badges or handlers (AC-14).
- **On merged develop the synthetic entry must flow through `catalogOutputs`**, or packaging and
  preview will not include it: audio is included only when it passes catalog freshness
  (`apps/api/src/services/catalog-output-service.ts`).
- **Filenames are the merged contract** (`storeImmutableAsset`), not the old `textId.hash` shape. The
  remap reads whatever the `tts` node recorded; it does not construct names.
- **Precedence, as a post-pass.** If the element already has a catalog entry of its own (a captioned
  image) or an `_easy_read` variant, the **authored audio under the element's `data-id` wins**. The
  remap runs **after** the ordinary maps are built, so ordering cannot flip the winner. It also
  removes any `${nodeId}_easy_read` key from `audios` and `audio_voices`: in easy-read mode
  `resolvePlayableAudio` (`useAudioPlayer.ts:74-82`) prefers `${id}_easy_read` when its translation
  exists, so leaving that key would play the caption's easy-read audio instead of the authored one
  (AC-18).
- **Display isolation.** The synthetic entry is speech, not display content. Packaging and the
  preview exclude it from `texts.json`; otherwise the script would appear as page text and could be
  word-highlighted under an id with no DOM element. It appears only in `speech_texts.json`,
  `audios.json`, `audio_voices.json` and `element_audio.json`.
- **Batching has one id-level home.** `speechPageId` (`speech.ts:4-5`) is the single membership
  rule. It returns `undefined` for `_easy_read` today; it must also return `undefined` for `_audio`.
  That one change keeps authored entries out of `computePageSpeechInputSignature`
  (`output-catalog.ts:222-224`), out of stage-runner's `pageById` (`stage-runner.ts:3098`), and out
  of every page group (`:3162`, `:3177`), without relying on the location's `pageId`.
- **Context isolation.** Page batching is not the only neighbour surface. Speech Preparation hashes
  `index-1`/`index+1` as `previous_display_text`/`next_display_text` (`packages/pipeline/src/core-tts.ts`),
  and ElevenLabs folds adjacent text into the cache key (`findAdjacentSpeechText`, `speech.ts:876`).
  A synthetic entry that became a neighbour would make editing one script invalidate a **real**
  element's preparation or audio. Therefore `_audio` entries are **appended after the page's rendered
  entries** and **excluded** from both neighbour lookups. One shared `isBatchableSpeechEntry()`
  owns the provider/config/page decision and replaces the inline expressions at `output-catalog.ts:222`,
  `:237`, `stage-runner.ts:3119-3122` (the `batchThisVoice` flag) and `tts.ts:980`; stage-runner's
  grouping inherits the id-level exclusion from `speechPageId`. AC-17 asserts all of it.
- **Timestamps stay behind.** The authored id is not republished in `tts-timestamps`; the player
  finds no word timings under the element id and uses block highlighting (AC-5).

**The remap is applied in two places**, or preview and bundle disagree:

1. `packages/pipeline/src/packaging/web.ts` (the bundle), and
2. the preview mirrors in `apps/api/src/routes/adt-preview.ts` — `speech_texts.json` (`:754`),
   `audios.json` (`:819`), `audio_voices.json` (`:845`), the new `element_audio.json`, and the audio
   bytes.

Both also exclude the synthetic entry from `texts.json` (`web.ts`, and
`adt-preview.ts:222-263`).

### 3. Generation is on demand, and staleness is hash-keyed

The script is saved immediately; **audio is generated when the author runs Speech**, never on save.

**Normalization.** A newly authored script enters the catalog as an ordinary source entry, so it
goes through **Speech Preparation** (`core-tts-catalog`), the step renamed in #947. With normalization
disabled for the book, display text is used unchanged; a failed preparation surfaces as a visible
`failed` state rather than silent absence (mirrors `CoreTtsSpeechEditor`'s Failed badge).

**What becomes stale.** Changing one element's script makes **only that element's** audio stale.
The reuse is **already hash-keyed on merged develop**: `computeSpeechCacheKey`
(`packages/pipeline/src/speech.ts:653`) and `canReuseSpeechEntry`
(`apps/api/src/services/stage-runner.ts:655`) compare the recorded hash against the current text, so
the changed entry is detected and regenerated **without deleting anything**. This is what the
isolation rules in §2 protect: without them, page batching, Speech Preparation neighbours or
ElevenLabs context would widen the invalidation to real entries on the same page. There is
therefore **no manual deletion step** and no `#710`-conditional branch.

**Restoring an earlier version of the script clears nothing.** `element-audio` is user-authored
content, not a derived output. On merged develop restore is uniform — `clearRestoredNodeDependents`
no longer has a per-node `switch` — so adding the node to `RestorableNode` is the whole change;
restoring an older script only makes the derived audio stale, which the hash reuse handles. It is
likewise not added to any other node's clear list.

### 4. The runtime adds the click trigger and the indicator

- **Only authored elements are targeted.** The runtime fetches the optional `element_audio.json` set
  with the other content manifests and binds only to those ids. An absent or empty file means no
  trigger and no badge, so existing books are untouched (AC-14, AC-20).
- A click on the element plays its audio (and stops the current one) via a **non-chaining** play path
  — `playAtIndex` chains on `ended` (`useAudioPlayer.ts:364-368`), so reusing it would read the whole
  section. `useAudioPlayer` keeps its `HTMLAudioElement` in the provider, so the trigger is a **React
  component** mounted inside `AudioPlayerProvider` (in `NavRoot`), not a plain `initializeX()`.
- **Sweep inclusion.** `gatherPlayableItems` builds the sweep from `[data-id]`, but the `items` memo
  filters out `<img>` unless `describeImagesMode` is on (`useAudioPlayer.ts:204`). An image listed in
  `element_audio.json` is included in the sweep **even when that mode is off**, so the click and the
  read-aloud sweep share the same authored file (AC-4).
- **The badge is added by the runtime, not the rendered HTML** (keeps the rendered HTML, the prompt
  contract and `validate-html.ts` untouched) and is a **sibling/overlay**, never a child of the
  `[data-id]` element: `applyTranslationsToDOM` rewrites element content
  (`features/language/runtime/i18n.ts:354`), which would remove a child badge.
- **Badge pointer behaviour.** The badge is `aria-hidden`, not focusable and not a second tab stop.
  A pointer click on it plays the element's audio and stops propagation, so it never triggers the
  Storyboard selection; keyboard users activate the element itself (Enter/Space). This is what makes
  the badge the play control in the preview (AC-10, AC-11).
- **Soft navigation.** #821 (merged) swaps `<main>` in place; #941 extends it to the desktop preview.
  The click handler and the badge must bind per **`pageEpoch`** (`app/lifecycle.ts`) with a disposer,
  or they double-attach / go stale across page turns.
- **In the Storyboard preview** a body click **selects** the element: the injected
  `iframe-interactive.ts` script reports the clicked `[data-id]` and
  `BookPreviewFrame.tsx:531` calls `onSelectElement`. The badge plays instead, so the two gestures
  are explicit and AC-11 is not a collision.
- Elements that are not audio-bearing keep today's behaviour exactly. Activity items and glossary
  terms are excluded (`EASY_READ_AUDIO_EXCLUDED_SELECTOR`, `useAudioPlayer.ts:49`); the trigger also
  ignores clicks that originate inside a link, button or other interactive descendant. A target with
  no accessible name (an `<img>` without `alt`, or an empty non-`img`) is left untouched (AC-9).

### 5. Accessibility is verified by a runtime test, with axe as a no-regression guard

`runAccessibilityAssessment` runs **axe-core** with `DEFAULT_AXE_RUN_ONLY_TAGS` including
`best-practice` and `cat.keyboard`; it runs in **JSDOM with `runScripts: "outside-only"`
(`accessibility-assessment.ts:130-133`)**, so it sees **only static attributes** — it cannot see
attributes the runtime adds, and it never executes the keyboard handler. The Playwright pass
(`apps/api/src/routes/package.ts:349-359`) only rechecks rules JSDOM flagged and is skipped when
Chromium is absent; it is best-effort and **not** evidence.

The attributes are therefore added **in runtime**, together with the behaviour, and verified by a
**jsdom runtime test with scripts enabled** (precedent: the activity runtimes set `role`/`tabindex`
at runtime, e.g.
`apps/adt-runtime/src/features/activity/runtime/activity-custom.ts:125-141`). The axe assessment
keeps running over the static HTML as a **no-regression** check.

The recipe below was **measured** against the audit's exact configuration, not derived:

| Shape | Result |
|---|---|
| `<img tabindex="0">`, no role | **clean** — `focus-order-semantics` is *inapplicable* to `<img>` |
| `<img tabindex="0" role="button" alt="Mago">` | clean |
| `<img tabindex="0" role="button">` with no `alt` | `aria-allowed-role` (minor) + `image-alt` (**critical**) |
| `<img tabindex="1">` (positive) | **`tabindex` (serious)** — never use a positive value |
| `<div tabindex="0">`, no role | **`focus-order-semantics` (minor)** |
| `<p tabindex="0" role="button" aria-label="…">` | clean |
| `<span role="button" tabindex="0">` with no accessible name | **`aria-command-name` (serious)** |
| a clickable element nested inside a `<button>` | **`nested-interactive` (serious)** |

- An `<img>` target needs only `tabindex="0"` plus a meaningful `alt`.
- A non-`img` target needs an interactive role **and** an accessible name once focusable.
- Never a positive `tabindex`; never nest inside another interactive control.
- The badge is `aria-hidden`, not focusable, and stops a pointer click so it plays without selecting
  the element in the preview; keyboard users activate the element.

## Acceptance criteria

- [ ] **AC-1** An author can select an **image** element in the Storyboard and save a spoken text for it; the text persists as a **new version** of the `element-audio` node for that page. The save carries `baseVersion`: two editors on different images of the same page **merge** without losing either edit, and the same `nodeId` changed on both sides returns **409** with the current version.
- [ ] **AC-2** After a pipeline run the element's audio exists on disk, and the packaged `speech_texts.json` / `audios.json` / `audio_voices.json` publish it **under the element's own `data-id`**; `element_audio.json` lists that id; the synthetic entry does **not** appear in `texts.json`. The entry flows through `catalogOutputs` freshness, uses the immutable filename contract, and its timestamps are not republished (AC-5).
- [ ] **AC-3** Clicking the element in the exported reader plays **only** that element's audio and pauses any audio already playing.
- [ ] **AC-4** The same element is played by the sequential read-aloud sweep using the **same** audio file (one audio, two triggers), including when `describeImagesMode` is off.
- [ ] **AC-5** An uncaptioned image (spoken text differs from any visible text) still gets audio; its word timestamps are not published under the element id, so the player uses block highlighting.
- [ ] **AC-6** The authored text **survives** re-running `easy-read` / `text-catalog` / `catalog-translation` / `core-tts-catalog` and changing the book's image set. On merged develop `clearNodesByType` only writes `NULL` invalidation versions for non-catalog rows, so nothing deletes it; `deletePage` and `clearExtractedData` still hard-delete and are documented non-goals.
- [ ] **AC-7** No code path adds `element-audio` to a clear/delete list; the checker fails CI if one is added. The checker scans **every** `clearNodesByType` literal (8 non-test call sites on merged develop) and the `deletePage` / `clearExtractedData` primitives, and asserts every `getStageRerunClearNodes` stage pair and `IMAGE_SET_CHANGE_CLEAR_NODE_TYPES`.
- [ ] **AC-8** Deleting an element **keeps** its authored text; duplicating a leaf produces a clone **without** audio and the UI says so; cloning a **section** does not inherit audio (documented non-goal).
- [ ] **AC-9** The clickable element carries, in runtime, `tabindex="0"` plus an accessible name (`alt` on `<img>`; role + name on non-`img`), never a positive `tabindex`, never nested in another interactive control; a target with no accessible name is left untouched. A **jsdom runtime test with scripts** asserts this **and** that Enter/Space fire the play path; the axe assessment reports **no new violations** on the static HTML.
- [ ] **AC-10** The visual indicator is decorative to assistive tech (`aria-hidden`), is not a second tab stop, and does not create a nested interactive control; a pointer click on it plays the element's audio and does not trigger the Storyboard selection.
- [ ] **AC-11** In the **Storyboard preview** the **badge** plays the element's audio while a body click keeps selecting the element (same bundle/manifests as the reader).
- [ ] **AC-12** A book whose `output_languages` equals its source language produces element audio with **zero** translation calls.
- [ ] **AC-13** All new user-visible strings are wrapped in Lingui macros and translated in `en`, `pt-BR`, `es`, `fr`, `sq`; the i18n CI job passes.
- [ ] **AC-14** Existing books (no `element-audio` node and no `element_audio.json`) open and export unchanged.
- [ ] **AC-15** Changing one element's script makes **only that element's** audio stale — including with `speech.batch_by_page`, Speech Preparation transformations, ElevenLabs context and easy-read mode enabled: the `_audio` entry never enters another entry's page context or neighbour window, the `${nodeId}_easy_read` audio key is removed so the easy-read lookup falls back to the authored file, and **nothing is deleted** (hash-keyed reuse); restoring an earlier script deletes nothing.
- [ ] **AC-16** An authored script goes through Speech Preparation; with normalization disabled the display text is used unchanged; a failed preparation is surfaced (not silent).
- [ ] **AC-17** `element-audio` entries are excluded at **`speechPageId`** (it returns `undefined` for `_audio`), so they never join a page batch or another entry's page context: `output-catalog.ts:222-224`, `stage-runner.ts:3098/3162/3177` and `tts.ts:980` all inherit that exclusion, and the remaining provider/config predicate is the single shared `isBatchableSpeechEntry()` at `output-catalog.ts:222/237`, `stage-runner.ts:3119-3122` and `tts.ts:980`.
- [ ] **AC-18** The authored audio under the element's `data-id` **takes precedence** over the element's own catalog entry / its `_easy_read` variant, in normal **and** easy-read modes, asserted by a test.
- [ ] **AC-19** `${imageId}_audio` is reserved as a derived id in both directions; a draft that introduces `X` and `X_audio` together is rejected, and the synthetic entry carries `locations: { pageId, sectionId, role: "element-audio" }` so it does not rely on the regex fallback.
- [ ] **AC-20** The runtime reads the optional `element_audio.json`; only ids listed there get the badge/trigger and the image sweep inclusion, and an absent manifest leaves existing books untouched.

## Rollout

Independently revertable PRs, each within the §9 review budget. **Nothing is user-visible until the
last one.** (The four are tracked as #895–#898 under #894.)

1. **PR 1 — plumbing, no UI.** `element-audio` schema + storage read/write + `buildTextCatalog`
   emitting synthetic entries + the `content-ids.ts` reservation of `${imageId}_audio` + the
   `speechPageId` id-level exclusion and the shared `isBatchableSpeechEntry()` predicate + node
   registration (`PipelineNodeName`, `NODE_CACHE_RESOURCES`) + the invariant row and its checker.
   Value: verifiable by test that an authored script produces audio without widening invalidation.

   `baseVersion` merge/409, and `RestorableNode` registration. Value: the script can be saved and
   versioned through the API.
3. **PR 3 — authoring.** The Storyboard inspector section in the **classic** `StyleEditorPanel`
   (unconditional pattern), the save-path wiring, `VersionedStep` registration, i18n. **Depends on the
   UI decision** recorded in the first review: it targets the classic UI now and a follow-up ports it
   to the new pipeline UI once #758 lands. Value: the author can write the script.
4. **PR 4 — playback.** The packaging remap (bundle **and** preview mirrors), including
   `element_audio.json`, the `texts.json` exclusion, the easy-read key removal and the withheld
   timestamps; the runtime manifest fetch, sweep inclusion, trigger and badge; the a11y attributes.

   hears it.
