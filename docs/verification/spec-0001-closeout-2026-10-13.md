Independent review rejected a proposed request-coalescing optimization: an old
initial/refetch response could overwrite committed state. Both late-response
cases are now regression tests; completion explicitly cancels matching old reads
before refreshing each book view. A run revision survives completed/cancelled job removal and queue transitions, changes on API restart, and is observed by polling even if all SSE events are missed. Recent receipts are deduplicated in the book query cache (last 32, subject to normal cache GC); this is not an exactly-once claim across arbitrary client lifetimes. Aggregate views refresh at run completion, while page/audio progress remains visible during execution. No stale cross-request cache was added.

`readSnapshot` is synchronous and joins an existing transaction. With this WASM
SQLite driver a competing writer is blocked until the snapshot returns; this is
not a claim of WAL concurrent-write support or a new writer-admission subsystem.
Tests prove rollback/release and that a subsequent read sees newly committed
versions. Publication guards still make a fresh read.

## Media hashing boundary

Ordinary catalog/page/status reads, active-reference packaging keys and reuse
checks do not read or hash media bytes. Known transcription identity is passed
through stage, single-item and batch routes; real filesystem + stubbed HTTP tests
prove zero binary hash inputs and no extra transport calls on unchanged reruns.
Unknown legacy audio and unpublished page audio derive their identity once.
Write-time immutable identity, one-time legacy snapshot and explicit restore
continue verifying bytes, as Note 1 explicitly requests. Existing multimodal LLM
request-cache/log hashing and PDF extraction hashing are outside this freshness
change and remain; this is not a repository-wide ban on media hashing. The
accepted gap is external same-name/same-ID corruption or replacement: ordinary
freshness reads trust recorded identity and availability; restore verifies bytes.

  Recommendation sent to the user: restore structural-edit attempt resets for these
  uncovered stages only, retaining data/history and cosmetic-save behavior. No
  response yet; current policy is not presented as ratified.

  400 before transport without OpenAI alignment credentials. Recommendation sent
  to the user: restore a true per-item Gemini path with per-item evidence when
  highlighting does not require alignment. No response yet; no change to page
  batches is implied.
- First-save alt interpretation: ignore empty/ID insertion placeholders, preserve
  meaningful authored text and reject new authoritative-caption conflicts. This
  deliberately narrows Note 2's “no previous alt” suggestion to preserve real user
  work; the spec now records the interpretation for review.
- I endorse the reviewer's never-attempted / failed / checked Core TTS distinction:
  a requested preparation run tries never-attempted fallback, failed unchanged
  fallback avoids automatic retry, and checked unchanged fallback remains accepted.
  ADR-024 now states the same rule; its status is still Proposed.
- No paid-provider quality/billing, signed installers, Windows/Linux Desktop GUI
  certification or release verification is claimed. No `lint:invariants` script
  exists; invariant coverage comes from repository tests, typecheck and lint.
