## Defect found by the UI walkthrough

On e7b9c702, catalog pg004's tree exclusion plus new text/image was saved through
the floating bar. SQLite retained `isPruned=true`, but the excluded paragraph
remained in saved HTML and preview after reload. The bar selected `saveRendering`
for a dirty rendering, bypassing `saveSectioning`'s exclusion reconciliation.
This is a real failed journey, not a fixture setup error.

Both Save entrypoints now use the sectioning path when a tree draft exists.
That path first flushes live inspector edits, then removes excluded elements
from that exact rendering snapshot. It retains draft state on failure, writes
new versions through the existing service, and makes no provider calls. It
still reports structural work that requires an explicit render.

A mounted `StoryboardSectionDetail` with the real `FloatingSaveProvider` tests
mixed exclusion/new text/new image/unflushed style, rejected Save then retry,
prune-only Save and an already-absent HTML leaf. Child editor/provider boundaries
are stubbed; persistence is covered separately by the real UI/SQLite journey.
The original four cases produce **two failures on published code and four
passes after the mixed-save fix**. Independent review then found a repeated-image
case: the same image can occur twice within one rendering, but exclusion removed
only its first occurrence. The helper now removes all matching local elements
while preserving other sections. A fifth mounted regression passes, including
the unchanged neighboring shared image. The real UI also added a second instance,
confirmed two occurrences, excluded the leaf, saved and reloaded: zero local
occurrences remained; pg004 and the glossary retained the shared reference and
the physical asset. [Screenshot](evidence/spec-0001-real-ui/repeated-image-excluded.jpg). The fresh pg003 real UI retest also passes. The pg004
failed snapshot was retained as before evidence; it was not silently repaired
and reported as an original pass.

## Acceptance handoff

The implementation is broader than the former safe slice, but this report does
**not declare full production acceptance**. Confidence is strongest for the
listed exercised paths. There is no substitute here for elasticsounds opening
actual De-codable pg006, duplicating/editing its custom activity, checking its
manual answer translations and exporting it. Exact saved books from the old
fixed-layout releases should also be checked; synthetic placement-map fixtures
prove the intended schema variants but cannot establish every historical book.

The legacy unique-leaf matching limitation remains an accepted assumption.
No migration framework or repair interface was introduced. A separate minor
UI inconsistency was observed during code review: the classic panel can offer
Regenerate for an unsupported custom type, whose handler rejects it safely;
this walkthrough does not claim that control was made usable for custom types.

Clean combined Docker `app`, Electron GUI, signed installers/other desktop
platforms, complete fresh-PDF CLI and paid-provider quality/billing remain
separate release/acceptance work. Previous Docker CI built the `api` target;
it is not a successful clean `app` build. The earlier local `app` build failed
with Debian package-signature errors while the Docker VM filesystem was full;
no unrelated Docker data was deleted to conceal that limit.

[Machine-readable storage assertions](evidence/spec-0001-real-ui/storage-assertions.json)
record retained versions, unchanged assets/scopes, shared IDs, request count and
ZIP contents. Synthetic UI screenshots are committed alongside this report.
Authentic book screenshots and raw snapshots remain local under
`/private/tmp/spec0001-real-ui-evidence/`; the original book data is not added to
the PR. Raw HTTP/provider logs and checks use `/private/tmp/spec0001-real-ui-*`.
