Catalog IDs and section-local DOM/activity identifiers are distinct namespaces.
Cloning changes text `data-id` values but preserves DOM IDs, selectors, ARIA links,
activity control keys, literal answers and accessible labels. A custom sorting
control using `data-id` as its legacy answer-key fallback receives an explicit
`data-activity-target` before its catalog ID changes.

A versionless legacy glossary edit uses unique retained-content/word evidence
only where its old ID is ambiguous. If ownership remains unprovable it receives
a fresh reserved ID; historical corrections remain retained. An editor version
that proves a unique current ID preserves that identity across renames. A stale
provided version returns 409 without writes. Studio keeps the rejected draft and
its original version even after a background refresh.

## Outstanding product decisions and limits

- **Unprovable section ownership:** Ordinary develop fixed-layout and new custom
  sections now have proven ownership. The narrow remaining ambiguous/contradictory
  legacy case retains raw content, versions and assets but omits that section from
  Preview/export with disclosure. The user delegated this safe choice with required
  documentation; human spec ratification or a safe repair workflow is still needed
  for unqualified AC-7/12 acceptance.
- **Divergent legacy Easy Read authority:** The first manual, otherwise first
  protected, otherwise first copy is displayed. All raw copies are retained and
  conflicting values cannot be accepted away. This explicit compatibility
  clarification remains pending human review, as recorded in the specification.
- **Two reviewer questions were expressly not ratified:** whether Quiz/Glossary/TOC
  structural edits should reset attempt status, and whether Gemini-only item
  generation under page-batch settings should bypass the OpenAI alignment-key
  requirement. Current behavior is retained pending a product decision; this
  audit does not claim those questions are resolved.
- **Media policy:** Following the review request, ordinary reads do not hash media
  bytes. Replacing/corrupting a nonempty file externally under the same identity
  is not detected by freshness reads; writes and explicit restore verify bytes.
  No automatic repair, background generation or separate locking system was added.
- No paid-provider quality/billing run, signed/notarized installer release,
  Windows/Linux Desktop runtime certification or release publication is claimed.
  `pnpm lint:invariants` is not defined; available invariant coverage runs through
  repository tests, typecheck and lint.
