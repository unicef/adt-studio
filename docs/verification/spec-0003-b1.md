## Scope, rollout and remaining decisions

This is **only the documented B1 safe slice**, not full SPEC-0003 completion.
It implements guarded mode publication, durable transition recovery, conservative
completion invalidation, persisted-data preflight and Studio confirmation.
B2 modes and cross-page merge are untouched.

Existing semantic Sectioning (including unknown/manual origin or inactive history)
is not regenerated. Existing extracted books cannot be re-extracted by the CLI/DAG
fallback. Storyboard with unknown lifecycle provenance is rejected even when its
section count happens to be valid. A fresh Sectioning run can establish provenance;
a mode change alone cannot. Thus changing mode on an existing book can leave it
inspectable but unable to regenerate until SPEC-0002 protection is implemented.
This limitation must remain visible at review and rollout; the selector does not
promise that this branch alone can complete an existing-book mode conversion.

The lifecycle file is a B1 completion/mode marker, not a replacement for SPEC-0001
freshness or SPEC-0002 provenance. The journal stores version, old/new YAML hashes,
new mode, derived affected steps and prior completion rows. Under the shared
book-local lease, old hash means no publication occurred; new hash completes
invalidation; any other hash fails closed. Readers do not trust unfinished journals.
The lease is shared by supported API writers, tasks, runners and CLI, uses canonical
book paths and does not steal a live or unknown owner based on elapsed time.
Recovery of a killed transition owner removes only its WASM mutex; SQLite journals
remain for SQLite recovery. A foreign/unknown owner or interrupted lock-reaper fails
closed for operator inspection. A confirmed-dead writer with an anonymous SQLite
mutex but no transition journal also fails closed, retaining owner and recovery
files; automatic recovery for this ordinary-transaction crash is not implemented.
Independent global-config edits are detected again
at rendering publication, and active version pointers are part of that comparison.

The two existing spec approval decisions remain pending: B1/B2 identity ratification
and storage-maintainer review of journal/admission representation. No approver or
release-verified status is fabricated. No acceptance criterion has been rewritten.
No alternative implementation PR was modified; #692 work is reused with attribution.

Do not deploy older writers against an unfinished journal, silently delete locks,
or downgrade past recovery support. No representative-book provider run, Windows/
Linux installer smoke, signed/notarized release or Docker image acceptance is claimed.
