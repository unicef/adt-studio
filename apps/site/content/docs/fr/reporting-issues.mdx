La meilleure façon de signaler un bug, de demander une fonctionnalité ou de
signaler quelque chose de déroutant est d'**ouvrir un ticket sur GitHub**. Les
tickets sont publics, consultables, et permettent à l'équipe de suivre et de
répondre à votre signalement. Vous n'avez pas besoin d'être développeur — cette
page vous guide pas à pas depuis le début.

## Créer un compte GitHub

Si vous n'en avez pas encore, il vous faudra un compte GitHub gratuit.

<Steps>

<Step>
### Allez sur la page d'inscription

Ouvrez [github.com/signup](https://github.com/signup) dans votre navigateur.
</Step>

<Step>
### Saisissez vos informations

Indiquez une adresse e-mail, un mot de passe et un nom d'utilisateur. GitHub
vous enverra un code par e-mail pour confirmer que c'est bien vous.
</Step>

<Step>
### Vérifiez et terminez

Saisissez le code reçu par e-mail. C'est tout — vous disposez désormais d'un
compte GitHub et pouvez créer des tickets.
</Step>

</Steps>

<Callout title="Vous avez déjà un compte ?">
Il vous suffit de [vous connecter](https://github.com/login) et de passer à la section suivante.
</Callout>

## Ouvrir un ticket

<Steps>

<Step>
### Ouvrez la page des tickets

Rendez-vous sur le suivi des tickets du projet :
[github.com/unicef/adt-studio/issues](https://github.com/unicef/adt-studio/issues).
</Step>

<Step>
### Recherchez d'abord

Tapez quelques mots-clés dans la barre de recherche pour vérifier si quelqu'un
a déjà signalé la même chose. Si vous trouvez un ticket correspondant, ajoutez
un commentaire ou une réaction 👍 plutôt que d'ouvrir un doublon — cela aide
l'équipe à évaluer le nombre de personnes concernées.
</Step>

<Step>
### Choisissez un modèle

Cliquez sur le bouton vert **New issue**. On vous demandera de choisir le modèle
correspondant à ce que vous signalez — choisissez le plus proche :

- **Bug Report** — quelque chose ne fonctionne pas comme prévu.
- **Feature Request** — proposez une nouvelle fonctionnalité ou une
  amélioration.
- **Accessibility Issue** — signalez un obstacle d'accessibilité dans
  l'application ou dans un livre qu'elle a produit.
- **Documentation Issue** — quelque chose dans cette documentation est faux,
  peu clair ou manquant.
- **Question / Support** — demandez comment faire quelque chose dans ADT Studio.
</Step>

<Step>
### Remplissez le formulaire

Chaque modèle est un court formulaire qui demande exactement ce dont l'équipe a
besoin : il suffit de suivre les champs. Quelques conseils pour un signalement
facile à traiter :

- **Un titre clair** — résumez-le en une ligne (par ex. *« L'audio ne se génère
  pas en portugais »*).
- **Ce qui s'est passé et ce que vous attendiez.**
- **Les étapes pour le reproduire** — ce sur quoi vous avez cliqué, dans
  l'ordre, afin que l'équipe puisse le constater elle aussi.
- **Votre configuration** — votre système d'exploitation (Windows, macOS ou
  Linux) et la version d'ADT Studio.
- **Des captures d'écran ou un enregistrement vidéo** — faites glisser les
  fichiers image directement dans la zone de texte. Une image en dit souvent
  plus qu'un paragraphe.
</Step>

<Step>
### Soumettez

Cliquez sur **Submit new issue**. Vous recevrez un e-mail à chaque réponse, et
vous pourrez répondre directement depuis votre boîte de réception ou sur la
page du ticket.
</Step>

</Steps>

<Callout type="warn" title="N'incluez pas d'informations sensibles">
Les tickets sont publics. Ne collez jamais de mots de passe, de clés d'API ou
de données personnelles dans un ticket — floutez-les ou supprimez-les d'abord
des captures d'écran.
</Callout>
