La mejor manera de informar de un error, solicitar una función o señalar algo
confuso es **abrir una incidencia en GitHub**. Las incidencias son públicas, se
pueden buscar y permiten al equipo hacer seguimiento y responder a tu reporte.
No necesitas ser desarrollador — esta página te guía paso a paso desde cero.

## Crear una cuenta de GitHub

Si todavía no tienes una, necesitarás una cuenta gratuita de GitHub.

<Steps>

<Step>
### Ve a la página de registro

Abre [github.com/signup](https://github.com/signup) en tu navegador.
</Step>

<Step>
### Introduce tus datos

Proporciona una dirección de correo electrónico, una contraseña y un nombre de
usuario. GitHub enviará un código a tu correo para confirmar que realmente eres
tú.
</Step>

<Step>
### Verifica y finaliza

Introduce el código de tu correo. Eso es todo — ya tienes una cuenta de GitHub y
puedes crear incidencias.
</Step>

</Steps>

<Callout title="¿Ya tienes una cuenta?">
Simplemente [inicia sesión](https://github.com/login) y pasa a la siguiente sección.
</Callout>

## Abrir una incidencia

<Steps>

<Step>
### Abre la página de incidencias

Ve al rastreador de incidencias del proyecto:
[github.com/unicef/adt-studio/issues](https://github.com/unicef/adt-studio/issues).
</Step>

<Step>
### Busca primero

Escribe algunas palabras clave en el cuadro de búsqueda para comprobar si alguien
ya ha reportado lo mismo. Si encuentras una incidencia que coincide, añade un
comentario o una reacción 👍 en lugar de abrir un duplicado — esto ayuda al
equipo a calcular cuántas personas se ven afectadas.
</Step>

<Step>
### Elige una plantilla

Haz clic en el botón verde **New issue**. Se te pedirá que elijas la plantilla
que corresponde a lo que vas a reportar — elige la más cercana:

- **Bug Report** — algo no funciona como debería.
- **Feature Request** — sugiere una nueva función o mejora.
- **Accessibility Issue** — informa de una barrera de accesibilidad en la app o
  en un libro que haya generado.
- **Documentation Issue** — algo en esta documentación está mal, poco claro o
  falta.
- **Question / Support** — pregunta cómo hacer algo en ADT Studio.
</Step>

<Step>
### Rellena el formulario

Cada plantilla es un formulario breve que pide exactamente lo que el equipo
necesita, así que basta con seguir los campos. Algunos consejos para un reporte
fácil de abordar:

- **Un título claro** — resúmelo en una línea (p. ej. *"El audio no se genera
  para portugués"*).
- **Qué ocurrió frente a qué esperabas.**
- **Pasos para reproducirlo** — en qué hiciste clic y en qué orden, para que el
  equipo también pueda verlo.
- **Tu configuración** — tu sistema operativo (Windows, macOS o Linux) y la
  versión de ADT Studio.
- **Capturas de pantalla o una grabación de pantalla** — arrastra los archivos
  de imagen directamente al cuadro de texto. Una imagen a menudo explica más que
  un párrafo.
</Step>

<Step>
### Envía

Haz clic en **Submit new issue**. Recibirás un correo electrónico cada vez que
alguien responda, y podrás responder directamente desde tu bandeja de entrada o
en la página de la incidencia.
</Step>

</Steps>

<Callout type="warn" title="No incluyas información sensible">
Las incidencias son públicas. Nunca pegues contraseñas, claves de API ni datos
personales en una incidencia — difumínalos o elimínalos primero de las capturas
de pantalla.
</Callout>
