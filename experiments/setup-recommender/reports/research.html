How should the Add Book flow pick settings?

Nine approaches tested on Victor's 6 PoC excerpts, 3 runs each, gpt-5.4-mini (plus gpt-5.4 for two of them). Every number below is from a run file in experiments/setup-recommender/results/poc/.

Recommendation

Keep "AI describes the book, the user confirms the facts, fixed rules pick the settings". Change how the AI decides which facts to put in front of the user. The model's own confidence never flagged a wrong answer, so don't use it. Ask the book questions in one call, label every page in a second cheap call, and highlight every fact where the two disagree. Always put the "What kind of book is this?" card first, because that answer drives 4 of the 6 settings. A chat that walks through all six settings asks more questions and needs expert judgement, so use it only for the "Why?" text on each setting. On gpt-5.4 both views were right on every fact, so the cross-check becomes a safety net.

Caveats

  • 4 scored books, 2 diagnostic. One wrong book moves agreement by about 11 points. A 100% here means "no miss on these four", nothing more.
  • The rulebook is in-sample. rules.ts and the thresholds in facts.ts were written while looking at these books, so E1's 18/18 and every "after correction" score are fits. I did not change either file. E5's counting thresholds were written before its first run and not changed after.
  • Some E5 wording targets a known failure. The page-type list says a foreword or preface counts as front matter, and the whole-book guess may use what a preface says. That is a standard definition, but I wrote it knowing El Viaje's excerpt is a publisher's note and a foreword.
  • Excerpts, not books. The PDFs have 7–12 pages. On El Viaje, 7 of 8 pages are cover, publisher's note and foreword, so no approach can see the story itself. A full book removes that problem and may bring others, such as long front matter or mixed chapters.
  • The true facts are mine. Where two answers are defensible, both count as correct, for example the workbook's composition.
  • The simulated user is perfect. Real users skip cards, misread options and accept wrong defaults. The effort numbers are a lower bound.
  • Spend: about 165 calls for the new runs (126 with gpt-5.4-mini, 36 with gpt-5.4, plus smoke tests). Token counts are reported, but not money, because prices change.

Next experiments

  • When the real converted books arrive: add them to a new dataset file, with labels taken from the settings the team actually shipped, plus true facts. Run e4, e5 and the cross-check without touching rules.ts. That gives the first out-of-sample score for the rulebook. Every rule that loses there needs a new fact, not a new threshold.
  • Run on whole books, not excerpts. Check that E5 still fits in one call (a 200-page book at low detail is about 17k image tokens), or label pages in batches.
  • Measure the flag rate on real books. If more than about 1 card per book is flagged, users will stop reading them.
  • Text-only path for providers without images: E6 loses mainly on "where does the text sit". That fact is measurable (textOverPictures), so for text-only providers let the measurement answer it.
  • Run a short session with 3–5 real users on the fact cards. Time each card, and count how often they accept a wrong default.
